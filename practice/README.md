# Практика вебинара 1 — «Что лежит в переменной»

Обычный Go-проект. Ничего скачивать не нужно: внешних зависимостей у модуля нет,
всё — стандартная библиотека. Достаточно установленного Go версии 1.22 или новее.

Сначала перейди в папку проекта. Выбери команду для своей копии материалов.

Из корня распакованного студенческого ZIP:

```bash
cd practice
```

Из корня полного репозитория:

```bash
cd series/go_basics/webinar_01/practice
```

В обоих случаях в текущей папке должен находиться файл `go.mod`.
Все следующие команды запускай из этой папки:

```bash
go version           # проверить, что Go на месте
go run ./cmd/demo    # посмотреть, что происходит с переменными
go test ./task1values ./task2slices ./task3zero   # три задачи эфира
go test ./...        # они же плюс домашнее задание
```

Эталона `../reference` в студенческом архиве **нет**. Команда `labcheck`
проверит твои задачи и сообщит, что проверка эталона пропущена.
В полном преподавательском репозитории эталон дополнительно проверяется
во временной копии, если каталог `../reference` существует.

## Как устроена работа

Три задачи эфира и домашнее задание, у каждого своя директория. В каждой лежит
файл с кодом и файл с тестами.
Код написан так, как его обычно пишут в первый раз, — и тесты показывают, где это
ломается. Ваша задача — сделать так, чтобы тесты прошли, не меняя сами тесты и не
меняя сигнатуры функций.

| Директория | О чём задача | Что запустить |
|------------|--------------|---------------|
| `task1values/` | копия или оригинал: структура, указатель, `range` | `go test ./task1values` |
| `task2slices/` | срез не хранит элементы: общий массив и `append` | `go test ./task2slices` |
| `task3zero/` | нулевое значение: `nil`-срез против `nil`-карты | `go test ./task3zero` |
| `homework/` | домашнее задание: те же три ошибки на складском учёте | `go test ./homework` |

Домашнее задание входит в `go test ./...` и до его выполнения падает — так и должно
быть. Задачи эфира — это первые три строки таблицы.

Места, которые нужно исправить, помечены комментарием `TODO(...)`. Найти их все:

```bash
grep -rn "TODO(" .
```

Тесты читать нужно — они написаны как объяснение, а не как приёмка. Сообщение
о провале говорит не только «не сошлось», но и почему.

## Проверить себя целиком

```bash
go run ./cmd/labcheck
```

Команда прогоняет тесты всех задач и печатает, что уже сходится, а что нет.
Если каталог `../reference` доступен (в полном преподавательском репозитории),
вторым прогоном проверяется эталон: эталонные файлы подменяют ваши во временной
копии, ваш исходный код не меняется. В студенческом архиве эталона нет,
поэтому этот прогон автоматически пропускается.
Так видно, что тесты в принципе проходимы, и что дело в коде, а не в тестах.

Если эталон смотреть не хочется, пока не решили сами:

```bash
go run ./cmd/labcheck -reference=""
```

## Эталонное решение

`../reference/` — по одному файлу на задачу и на домашнее задание, с теми же
именами и теми же путями.
Эталон существует в полном преподавательском репозитории, но в студенческий
архив не входит. Преподаватель может открыть его для разбора после дедлайна.

## Ожидаемый прогресс

- В исходном архиве: **17/37** тестов проходят.
- После трёх задач эфира: **32/37**; пять красных относятся только к Д/З.
- После домашнего задания: **37/37** (всё зелёное).

## Что считается сделанным

На эфире — три задачи: `go test ./task1values ./task2slices ./task3zero` проходит
целиком. Дома — то же самое плюс `homework/`, то есть `go test ./...` целиком.

Условие домашнего задания, объём и дедлайн — в `../docs/03_Домашнее_задание.md`.
Ничего, кроме стандартной библиотеки, оно не требует.
